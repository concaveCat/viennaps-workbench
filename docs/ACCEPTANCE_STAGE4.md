# Stage 4: solver controls, single flux calculation, and native fields

Status: implemented and passed automated Python and real Chromium acceptance. The formal baseline at `/root/viennaps-workbench-selectivity` and its service on port 8769 were not modified.

## Implementation

- Extended the unified project format to schema 7 while retaining schemas 1–6, including the schema 6 native continuation contract. Advanced ViennaLS and ray parameters live under the solver settings and participate in validation and input hashing only when applicable.
- The bounded worker maps advanced solver settings to the installed `viennaps.AdvectionParameters` and `viennaps.RayTracingParameters`, sets them on `viennaps.Process`, and records native readback, engine, random seed, threads, and installed versions.
- Single flux uses `Process.calculateFlux()` and returns without calling `Process.apply()`. The service records ViennaPS mesh points/topology, scalar and vector fields with their original point/cell association, native names/types and undeclared-unit status, and a mesh identity. Native VTP and JSON/CSV exports are available through history and run ZIPs.
- ViennaLS velocity/dissipation output is generated by the actual solver. Because ViennaLS 5.8.5 writes these files relative to the process working directory despite the output-path setter, every step gets a per-run isolated working directory inside the bounded child. The raw VTP and SHA-256 are preserved and included in result exports.
- The browser decodes the installed writer's appended base64/zlib VTP arrays without changing mesh or field association. It verifies SHA-256, point and cell counts, coordinates, topology offsets/indices, field names/types/components/tuple counts against the API manifest before displaying CSV values. The downloadable VTP remains the original native file.

## Limits and review points

- ViennaPS/ViennaLS native mesh bindings do not declare physical units for `particleFlux`, `Normals`, `AdvectionVelocities`, or `Dissipation`; the UI preserves values and reports the units as unspecified rather than inferring them.
- The browser field reader supports the installed writer's base64 appended data and zlib compression. Other VTK encodings remain downloadable as raw output but are not parsed into the table.
- Only fields actually emitted by the installed models are exposed. This stage adds no synthetic coverage, flux, or velocity fields.
- GPU capability remains host-unverified; Stage 9 will audit actual supported combinations and explicit-GPU failure behavior.
- Items for independent review: native VTP parser bounds and topology checks; schema-7 legacy/hash behavior; intermediate-output worker CWD isolation; correct reading of native model fields without unit metadata.

Stage 4 completion does not imply Stages 5–9 are complete.

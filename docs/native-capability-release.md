# Native capability release: GPU_TRIANGLE, any-axis Slice, half geometries

This release exposes three capabilities that already exist in the installed
ViennaPS 4.6.2 bindings. Each one is opt-in, records what the native call
actually did, and fails instead of silently falling back or widening a shape.

## 1. GPU_TRIANGLE

### Request

Schema 7 only:

```json
{
  "solver": {
    "enginePreference": "gpu",
    "gpuEngine": "GPU_TRIANGLE",
    "gpuDeviceId": "GPU-..."
  }
}
```

`gpuEngine` accepts `GPU_DISK` or `GPU_TRIANGLE`. It is optional; when omitted
the historical `GPU_DISK` route is used and request hashes are unchanged.
`gpuEngine` requires `enginePreference: "gpu"`. The applied solver hash includes
`gpuEngine` when it is set, and `executionHash` always includes the selected
step engine, so replay cannot reinterpret a run under a different engine.

### Evidence scope

Exactly two capability rows are published in
`docs/stage9-evidence/gpu-capability-matrix.json`:

| Dimension | Model | Operation | Boundary | Geometry | Pattern | Materials |
| --- | --- | --- | --- | --- | --- | --- |
| 2 | `specialized:sf6o2` | etch | reflective | stack | none | Si (bulk), SiO2 (film), Si3N4 (mask) |
| 3 | `specialized:sf6o2` | etch | reflective | stack | none | Si (bulk), SiO2 (film), Si3N4 (mask) |

They come from
`docs/stage9-evidence/gpu-variants/gpu-triangle-{2d,3d}/summary-gpu_triangle.json`,
where the Stage 8 product worker and an independent direct ViennaPS call
matched on initial/final coordinates, topology, material arrays and material
mapping, and both recorded the RTX 3060 UUID from the CUDA runtime readback.
The rows are generated by `add_gpu_triangle_rows()` in
`tests/fixtures/derive_stage9_gpu_matrix.py`; the full `GPU_DISK` matrix is not
widened by inference.

`AUTO` still prefers `GPU_DISK` then `CPU_DISK`; it never selects
`GPU_TRIANGLE` implicitly. `GPU_LINE` remains unexposed.

### Rejection and no fallback

A request that selects `GPU_TRIANGLE` for anything outside the table returns
HTTP 422 with a message naming the uncovered model, operation, boundary and
dimension. The engine selector returns `unavailable`; it does not try
`GPU_DISK` or `CPU_DISK`. Replay applies the same evidence check and also
rejects a recorded engine that differs from `solver.gpuEngine`.

The run manifest records `plannedExecution[].engine = GPU_TRIANGLE`,
`plannedExecution[].gpuDeviceId`, `actualExecution[].actualEngine =
GPU_TRIANGLE`, and the worker's `cudaDeviceReadback` (UUID/PCI bus/readback
status).

## 2. Any-axis Slice

### Request

```json
{
  "project": { "...": "schema-7 3D geometry project without steps" },
  "sliceRequest": {
    "sliceAxis": "x",
    "position": 0.0,
    "reflectX": false
  }
}
```

`sliceAxis` is a strict optional enum `x | y | z`. Omitting it keeps the
historical y-normal slice. `reflectX` is a strict optional boolean and maps to
native `Slice.setReflectX`; omitting it means `false`.

The legacy integer `axis` field is retained and still defaults to `1`. A
default request normalizes to exactly `{"axis": 1, "position": ...}`, so
existing request hashes and replay documents are unchanged.

### Native mapping

`sliceAxis` maps to `Slice.setSliceDimension(0/1/2)`:

| `sliceAxis` | Native dimension | Plane normal | Output x/h coordinates |
| --- | --- | --- | --- |
| `x` | 0 | `[1,0,0]` | source y / source z |
| `y` | 1 | `[0,1,0]` | source x / source z |
| `z` | 2 | `[0,0,1]` | source x / source y |

The output 2D domain lateral extent follows the mapped coordinate
(`yExtent` for x-normal, `xExtent` for y- and z-normal). x/y positions are
bounded by that lateral half-extent; z positions must lie inside the source
surface z range. The worker rounds the position to the native grid and records
both `requestedPosition` and the actual `position`. A slice plane with no
defined points raises instead of exporting an empty mesh.

`sliceReadback` records `axis`, `axisName`, `planeNormal`,
`outputCoordinateMapping`, `reflectX`, requested/actual position,
`outputLateralExtent`, `levelCount` and the native material map. A 2D project
is rejected with a 422 that names the requested axis.

## 3. HoleShape HALF/QUARTER and halfFin/halfTrench

### Request fields

| Geometry | Field | Values | Default | Native call |
| --- | --- | --- | --- | --- |
| hole | `holeShape` | `FULL`, `HALF`, `QUARTER` | omitted = FULL | `MakeHole(..., holeShape=ps.HoleShape.<value>)` |
| trench | `halfTrench` | boolean | omitted = false | `MakeTrench(..., halfTrench=...)` |
| fin | `halfFin` | boolean | omitted = false | `MakeFin(..., halfFin=...)` |

All three are strict optional fields. Omitting them leaves the normalized
geometry unchanged, so historical request hashes stay identical (verified for
2D/3D hole, trench and fin fixtures).

HALF keeps the native `x >= 0` half (`halveXAxis`); QUARTER additionally keeps
`y >= 0` (`halveYAxis`) and is 3D-hole only. The worker records
`actualHoleShape`, `actualHalfTrench`, and `halfFin` in the initial
`geometryReadback`, and the Boolean fin fallback explicitly applies
`halveXAxis` so the flag is not lost when the native MakeFin route is skipped.

### Validation

The installed binding only logs a warning and silently widens/ignores these
flags with periodic boundaries (and 2D `MakeHole` natively becomes a trench).
The Workbench therefore returns 422 for:

- `holeShape` HALF/QUARTER in a 2D project;
- `holeShape` HALF/QUARTER with a periodic boundary;
- `halfTrench: true` with a periodic boundary;
- `halfFin: true` with a periodic boundary;
- any value outside the strict enum.

There is no silent full-shape fallback.

## Tests

`tests/test_native_capability_release.py` covers:

- GPU_TRIANGLE matrix scope, validation/routing, 422 for an unproven
  combination, real 2D and 3D product/direct comparison, selected UUID,
  actual engine identity and replay. The GPU cases skip with the device reason
  if the sandbox cannot reach CUDA.
- x/y/z slices on a 3D geometry against an independent native Slice, plane
  normals, output coordinate extents, reflect-X mirroring, default hash
  stability, 2D rejection, invalid axes and replay.
- HALF/QUARTER/halfFin/halfTrench product/direct comparisons in 2D and 3D,
  x/y bounds, QUARTER symmetry, omitted-hash stability, invalid combinations
  and replay.

`tests/fixtures/stage5_geometry_reference.py` was extended to call the same
native constructors/arguments directly for trenches, holes and half shapes,
and to slice along any axis with optional reflection.

## Refused capabilities

- `GPU_TRIANGLE` for every model/dimension/boundary/geometry other than the
  two rows above: no product+direct evidence.
- `GPU_LINE`: no product worker comparison, WebUI save/replay or CUDA UUID.
- 2D `holeShape` HALF/QUARTER: the Workbench has no 2D hole geometry (native
  `MakeHole` in 2D is a trench); use `halfTrench` explicitly.
- Half shapes with periodic boundaries: native silently widens/ignores them.
